# Платформа совместных спортивных активностей «Спортик»

Прототип кейса Столото: адаптивное веб-приложение для поиска и организации совместных спортивных мероприятий (запись, обсуждение, роли пользователь / организация / администратор).

---

## Запуск

**Требования:** Docker, Docker Compose. Порты **8080** (сайт), **8000** (API).

```bash
cp .env.example .env
# Укажите GEO_CONTACT_EMAIL и ADMIN_EMAIL (см. ниже)
docker compose up -d --build
```

| Адрес | Назначение |
|-------|------------|
| http://localhost:8080 | Веб-приложение |
| http://localhost:8000/docs | OpenAPI |
| http://localhost:8000/health | Проверка API и БД |

Миграции БД выполняются сервисом `migrate` при старте (`alembic upgrade head`).

### Переменные окружения

| Переменная | Назначение |
|------------|------------|
| `ADMIN_EMAIL` | Email, с которым нужно **зарегистрироваться** на `/register` — получит роль администратора (`/admin`) |
| `GEO_CONTACT_EMAIL` | Контакт для Nominatim (подсказки адреса); без него автодополнение адреса может не работать |
| `SEED_MOCK_DATA` | `true` — демо-события в **Красноярске** при пустой БД |
| `CORS_ORIGINS` | Origins через запятую; на HTTPS-стенде добавьте URL фронта |
| `COOKIE_SECURE` | `true` на HTTPS, иначе вход не сохранится |

Пароль администратора и остальных пользователей задаётся при регистрации (отдельных демо-паролей в репозитории нет).

### Роли для проверки

| Роль | Как получить |
|------|----------------|
| Администратор | Регистрация с email из `ADMIN_EMAIL` |
| Обычный пользователь | Регистрация, тип «пользователь» |
| Организация | Регистрация, тип «организация» → допуск в `/admin` |

**Имитации (по условиям кейса):** нет подтверждения email, SMS, OAuth, восстановления пароля. Регистрация, сессии, заявки, модерация и записи — **рабочие** (данные в PostgreSQL).

## Демонстрационные данные

При `SEED_MOCK_DATA=true` и отсутствии зарегистрированных пользователей в БД создаются события в **Красноярске**: волейбол (свободная запись), шахматы (по заявке), бег, футбол; одобренная организация «Клуб „Север“»; примеры комментариев и заявки. Профили seed-организаторов в ленте **без входа** (только наполнение каталога).

## Шесть базовых сценариев

### 1. Создание мероприятия пользователем

Вход → `/create-event` → название, вид спорта (из списка или **новый** через заявку → одобрение в `/admin`), дата, адрес, режим записи, уровень. Под другим аккаунтом: найти в `/` или `/events`, открыть карточку.

### 2. Допуск организации и публикация

Регистрация как организация → `/org` (до допуска публикация недоступна). Админ `/admin` → одобрить/отклонить (причина при отклонении). После одобрения — создать событие; проверить `/organizations/{id}` другим пользователем.

### 3. Свободное присоединение

Событие с режимом **«Свободная»** (seed: «Волейбол на Цимлянской» или своё). Запись → статус подтверждён; организатор видит участника.

### 4. Участие по заявке

Событие **«По заявке»** (seed: «Шахматный вечер»). Заявка → ожидание. Организатор: **Принять** / **Отклонить** на карточке события; проверить статус у заявителя (обе ветки).

### 5. Уточнение условий

`/events/{id}/discussion` — вопрос пользователя, ответ организатора; авторы различимы.

### 6. Снятие с публикации

Админ `/admin` → снять событие. Нет в выдаче для записи, на карточке — снято с публикации, запись недоступна.

Универсальность: в ленте/каталоге видны разные виды спорта в одном приложении.

## Дополнительные возможности (где проверять)

| Функция | Где |
|---------|-----|
| Заявка на новый вид спорта | Создание события / `/admin` |
| Лист ожидания, избранное, уведомления | Карточка события, `/notifications` |
| Подсказки адреса, геокод города | Создание события, выбор города |
| Подписки, публичный профиль | `/users/{id}`, профиль |
| Discovery (свайпы) | `/discovery` |
| Команды, запись командой | Профиль → команды; API join-team |
| Посещаемость (7 дней после старта), надёжность % | Карточка события (организатор); `/profile` |
| Оценки: дружелюбие (участники), скилл (организатор, только open) | Карточка **прошедшего** события, блок «Оценки участников» |
| Спортик (тамагочи, 3D) | `/sportik` (вход обязателен) |
| Модерация спортов, событий, организаций | `/admin` |

## Стек и структура

**Стек:** React + TypeScript + Vite; FastAPI; PostgreSQL 17; Redis (кэш публичного списка событий по городу, без сессий); Docker Compose.

**Структура:** `backend/app/` — API; `backend/migrations/` — Alembic; `frontend/src/` — SPA; `docker-compose.yml` — окружение.

**Внешние сервисы:** [Nominatim](https://nominatim.openstreetmap.org/) (адреса, нужен `GEO_CONTACT_EMAIL`; лимиты частоты). Яндекс.Карты — только ссылка из карточки события. Геолокация браузера: localhost или HTTPS.

**Ограничения прототипа:** лента ориентирована на выбранный город; посещаемость и оценки — в течение 7 суток после начала события; визиты Спортика и надёжность — по отметке организатора «был»; нет SMS/OAuth/бронирования площадок.
