# Спортик

React/Vite-фронтенд и FastAPI API. Источник данных — PostgreSQL: учётные записи, профили, мероприятия, записи, обсуждения, избранное и серверные сессии. Redis хранит **только** короткий публичный кэш списка мероприятий по городам; сессий и паролей там нет. Исходные демо-пользователи/события удаляются миграцией `0002`; роли/права и справочник видов спорта остаются.

## Локальный запуск Docker

В корне проекта создайте `.env` из `.env.example` и заполните его. Для геолокации укажите настоящий `GEO_CONTACT_EMAIL` — он нужен сервису Nominatim. Затем:

```bash
docker compose up -d --build
docker compose ps
```

Приложение: http://localhost:8080, API: http://localhost:8000/docs, проверка БД: http://localhost:8000/health. При первом запуске Compose сам выполнит Alembic. Зарегистрируйте новый аккаунт через `/register`; демо-логина больше нет. Для локального Vite: `cd frontend && npm ci && npm run dev` (порт 5173, прокси `/api` на localhost:8000). Для backend без Docker: установите `backend/requirements.txt`, задайте переменные из `backend/.env.example`, из `backend/` выполните `alembic upgrade head && uvicorn app.main:app --reload` при доступных PostgreSQL/Redis.

После обновления файлов локально выполните `docker compose up -d --build`. Скрипт `scripts/apply-update.ps1` для PowerShell сначала применяет миграции, затем перезапускает Redis и пересобирает backend/frontend. После успешных изменений событий, профилей и обсуждений через API backend перезапускает Redis (`SHUTDOWN NOSAVE`); Compose поднимет его снова. В промежутке чтение идёт напрямую из PostgreSQL. Кэш не содержит личных данных, потому что `/api/v1/state` всегда запрашивает PostgreSQL.

### Переход со старой демо-версии

Ревизия `0002` удаляет **только известный неизменённый демо-набор** из `0001`; если обнаружены другие пользователи, события, комментарии, заявки и т. д., миграция останавливается без удаления данных. Для действительно чистого старта сначала сделайте резервную копию нужных данных, затем **осознанно** удалите тома проекта командой `docker compose down -v` и запустите `docker compose up -d --build`. `down -v` безвозвратно удалит PostgreSQL-данные и загруженные аватары данного Compose-проекта — не запускайте её на рабочей базе без резервной копии.

## Авторизация и личные данные

Регистрация и вход — email + пароль (Argon2). Сессия хранится в PostgreSQL, браузер получает HttpOnly SameSite=Lax cookie; выход отзывает сессию. Гости могут просматривать опубликованные события и обсуждения; создание и редактирование своих событий, запись, сообщения, лайки и редактирование профиля требуют входа. Редактировать заявки и мероприятия вправе только их организатор. Аватары JPEG/PNG/WebP до 5 МБ лежат в отдельном Docker-томе `avatars_data` и доступны по `/media/{id}`. Содержимое файлов не хранится в JSON и не попадает в Redis.

Браузер предлагает выбрать город и по нажатию кнопки может запросить разрешение на геолокацию; координаты отправляются backend для обратного геокодирования через Nominatim, а в профиле сохраняется **только город**, не точные координаты. При отказе или ошибке город можно ввести вручную. Геолокация браузера работает в безопасном контексте: **localhost или HTTPS**, не по обычному HTTP на публичном IP. У Nominatim есть ограничения на частоту запросов; для нагрузки замените сервис на свой геокодер.

## Развёртывание на сервере

`frontend/` — самодостаточный Vite-проект (`src/`, `public/`, `package.json` и Dockerfile); `backend/` содержит API и миграции. На сервере настройте HTTPS и добавьте публичный адрес фронтенда **с протоколом и без завершающего `/`** в `CORS_ORIGINS` файла `.env`, например `CORS_ORIGINS=https://sport.example.ru`. Для HTTPS задайте `COOKIE_SECURE=true`; иначе вход не будет работать корректно или cookie окажется незащищённой. На `http://IP` геолокация браузера не работает: используйте ручной выбор города до настройки HTTPS. Вход и любые POST/PATCH защищены проверкой Origin; если получаете 403, проверьте `CORS_ORIGINS`. Проксируйте весь сайт с системного Nginx на локальный порт `8080`: контейнерный Nginx уже направляет `/api/` и `/media/` в FastAPI. Не публикуйте PostgreSQL и Redis в интернет.

## Проверка

```bash
cd frontend && npm ci && npm run build
cd ../backend && python -m pytest -q
```

Для интеграционной проверки нужны контейнеры: регистрация → выбор города → создание мероприятия → вход вторым аккаунтом → запись и сообщение → повторное открытие страницы и проверка сохранения в PostgreSQL. Сборка/интеграционные тесты не были выполнены в этой рабочей среде: загрузка npm/pip зависимостей недоступна; перед переносом на сервер выполните указанные команды локально.
